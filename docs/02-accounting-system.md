# وثيقة النظام المحاسبي المتكامل
### منصة B2B — Super Admin + Suppliers | الإصدار 1.0

---

## 1. فلسفة التصميم

### 1.1 المبادئ الخمسة غير القابلة للتفاوض

| # | المبدأ | التطبيق |
|---|---|---|
| 1 | **القيد المزدوج (Double-Entry)** | لا توجد "حركة مالية" — يوجد **قيد** دائماً متوازن: مجموع المدين = مجموع الدائن |
| 2 | **ثبات السجل (Immutability)** | القيد المرحّل لا يُعدَّل ولا يُحذف. التصحيح بقيد عكسي (Reversal) يحمل مرجع الأصل |
| 3 | **الأتمتة الكاملة** | المستخدم لا يُدخل قيوداً يدوية في الحالات الاعتيادية — النظام يولّدها من الأحداث |
| 4 | **العزل التام** | دفتر المنصة ودفاتر الموردين منفصلة تماماً. لا يرى المورد قيود المنصة ولا قيود مورد آخر |
| 5 | **قابلية التدقيق** | كل قيد يرجع لمستند مصدر (Source Document) ولمستخدم وزمن وIP |

### 1.2 المستويان المحاسبيان

```
┌──────────────────────────────────────────────────────────┐
│  دفتر المنصة (Platform Ledger) — Super Admin             │
│  tenant_type = platform                                   │
│  إيرادات: عمولات، اشتراكات، رسوم إعلان، رسوم خدمات       │
│  مصروفات: رواتب، استضافة، تسويق، رسوم بوابات الدفع       │
│  التزامات: أموال محتفظ بها لصالح الموردين (Escrow)        │
└──────────────────────────────────────────────────────────┘
                          ▲
                          │ العمولة = إيراد للمنصة / مصروف للمورد
                          ▼
┌──────────────────────────────────────────────────────────┐
│  دفتر المورد (Supplier Ledger) — لكل مورد مستقل          │
│  tenant_type = supplier, tenant_id = N                    │
│  إيرادات: المبيعات، الشحن المحصّل                         │
│  تكاليف: تكلفة البضاعة المباعة، عمولة المنصة، الشحن       │
│  أصول: المخزون، العملاء (ذمم مدينة)، النقدية، محفظة المنصة │
└──────────────────────────────────────────────────────────┘
```

> **نقطة مفصلية:** عملية بيع واحدة تولّد **قيدين منفصلين** — واحد في دفتر المورد (مبيعات) وواحد في دفتر المنصة (إيراد عمولة + التزام تجاه المورد). لا يختلط الدفتران أبداً.

## 3. محرك القيود الآلي (Journal Engine)

### 3.1 آلية العمل

```
حدث تجاري (Domain Event)
        │
        ▼
  Accounting Listener
        │
        ▼
  Posting Rule (قاعدة ترحيل معرّفة لكل نوع حدث)
        │
        ├─> تحديد الحسابات من خريطة الحسابات (Account Mapping)
        ├─> حساب المبالغ والضرائب والعملة
        ├─> التحقق من التوازن (مدين = دائن) ← يفشل القيد وإلا
        └─> إنشاء JournalEntry + JournalLines داخل DB Transaction
                │
                ▼
         تحديث أرصدة الحسابات (Account Balances)
```

**قواعد تنفيذية:**
- كل قيد يُنشأ داخل معاملة قاعدة بيانات واحدة مع الحدث المسبّب — إما ينجح الاثنان أو يفشلان.
- مفتاح `idempotency_key = {event_type}:{source_type}:{source_id}` يمنع تكرار القيد.
- القيد يبدأ `draft` ثم `posted`؛ لا ترحيل في فترة مقفلة (Closed Period).
- إلغاء أي مستند ⟵ قيد عكسي جديد وليس حذفاً.

## 4. محرك الضرائب (Tax Engine)

لا تُكتب نسب الضريبة في الكود. يُبنى محرك قابل للتهيئة:

- **Tax Codes:** كل كود يحمل (الاسم، النسبة، النوع: شامل/مضاف، الحساب المحاسبي، البلد، تاريخ السريان).
- **قواعد التطبيق:** حسب بلد المورد + بلد المشتري + فئة المنتج (معفى / صفري / خاضع).
- **التصدير:** مبيعات التصدير عادةً بنسبة صفر مع إثبات التصدير — مدعومة كحالة خاصة.
- **الاحتجاز (Withholding Tax):** مدعوم على مدفوعات الخدمات.
- **تقرير الإقرار الضريبي:** ضريبة المخرجات − ضريبة المدخلات = المستحق، بصيغة قابلة للتصدير.
- **الفوترة الإلكترونية:** بنية الفاتورة تتضمن الحقول المطلوبة (UUID، رمز QR، التجزئة التسلسلية Hash Chain) لتسهيل الربط مع هيئة الضرائب لاحقاً.

## 5. العملات المتعددة

| البند | القاعدة |
|---|---|
| عملة الدفتر (Functional Currency) | تُحدَّد لكل مستأجر مرة واحدة ولا تتغيّر |
| عملة المعاملة | أي عملة؛ تُخزَّن مع سعر الصرف وتاريخه |
| التخزين | كل سطر قيد يحمل: `amount`, `currency`, `exchange_rate`, `base_amount` |
| الأرصدة | تُحتسب دائماً بعملة الدفتر |
| فروق التسوية | عند السداد بسعر مختلف ⟵ قيد فرق عملة (ربح/خسارة) تلقائي |
| إعادة التقييم | في نهاية الفترة للحسابات بالعملات الأجنبية |
| أسعار الصرف | جدول يومي، تحديث آلي من مزوّد + إمكانية الإدخال اليدوي |

> **قاعدة حاسمة:** كل المبالغ تُخزَّن كأعداد صحيحة بوحدة فرعية (Minor Units) — 10,000 ريال = `1000000` بالهللات — لتفادي أخطاء الفاصلة العائمة نهائياً.

## 6. التقارير والقوائم المالية

### 6.1 تقارير تشغيلية

| التقرير | المستفيد |
|---|---|
| كشف حساب عميل | المورد |
| أعمار الذمم المدينة (0-30 / 31-60 / 61-90 / +90) | المورد + المنصة |
| أعمار الذمم الدائنة | المورد |
| تقرير المبيعات (بالمنتج/العميل/الفترة/المندوب) | المورد |
| تقرير المخزون وحركة الأصناف | المورد |
| تقرير الأصناف الراكدة وتحت الحد الأدنى | المورد |
| ربحية المنتج / ربحية العميل | المورد |
| تقرير العمولات المستحقة والمحصّلة | المنصة |
| تقرير التسويات والمدفوعات للموردين | المنصة |
| تقرير الاشتراكات والتجديدات | المنصة |
| تقرير الإيراد الشهري المتكرر (MRR/ARR) | المنصة |

### 6.2 القوائم المالية الرسمية

لكل مستأجر (مورد) وللمنصة، عن أي فترة، وبإمكانية المقارنة مع فترة سابقة:

1. **ميزان المراجعة (Trial Balance)** — بالأرصدة والحركات، مع تحقق إلزامي من التوازن.
2. **قائمة الدخل (Income Statement)** — إيرادات − تكلفة مبيعات = مجمل الربح − مصروفات = صافي الربح.
3. **قائمة المركز المالي (Balance Sheet)** — الأصول = الالتزامات + حقوق الملكية.
4. **قائمة التدفقات النقدية (Cash Flow)** — بالطريقة غير المباشرة.
5. **دفتر الأستاذ العام (General Ledger)** — حركات كل حساب بالتسلسل مع الرصيد الجاري.
6. **دفتر اليومية (Journal)** — كل القيود بالتسلسل الزمني.

## 7. إقفال الفترات والسنة المالية

```
فترة مفتوحة ──> مراجعة ──> قفل مبدئي (Soft Close) ──> قفل نهائي (Hard Close)
```

- **السنة المالية** قابلة للتهيئة (تبدأ يناير أو أي شهر).
- **القفل المبدئي:** يمنع الترحيل العادي، يسمح لمحاسب معتمد بقيود تسوية.
- **القفل النهائي:** لا ترحيل إطلاقاً؛ أي تعديل يتطلب فتحاً موثّقاً بسبب ومستخدم.
- **قيود الإقفال السنوي:** إقفال الإيرادات والمصروفات في حساب ملخص الدخل (3900)، ثم ترحيل الصافي إلى الأرباح المحتجزة (3200)، وفتح الفترة الجديدة بالأرصدة الافتتاحية للحسابات الدائمة.
- **قيود التسوية الدورية:** الإهلاك، المصروفات المستحقة، المقدمة، مخصص الديون — قابلة للجدولة (Recurring Journals).

---

## 8. المطابقة البنكية (Bank Reconciliation)

- استيراد كشف الحساب البنكي (CSV / MT940 / Open Banking API).
- مطابقة آلية مقترحة بالمبلغ والتاريخ والمرجع، مع مطابقة يدوية للباقي.
- حالات كل حركة: `unmatched / matched / ignored`.
- تقرير التسوية البنكية: رصيد الدفاتر ⟷ رصيد البنك مع بنود التسوية (شيكات معلّقة، إيداعات في الطريق).

## 11. نموذج العمولات والاشتراكات

### 11.1 العمولة
- نسبة مئوية، أو مبلغ ثابت، أو **متدرجة** (مثلاً 8% حتى 50 ألف، 6% فوقها).
- قابلة للتخصيص: عامة → حسب الفئة → حسب خطة المورد → حسب مورد بعينه (الأخص يفوز).
- لحظة الاستحقاق قابلة للتهيئة: عند التأكيد / عند الشحن / **عند التسليم (موصى به)**.
- معالجة الاسترداد: عكس العمولة تلقائياً بنسبة المبلغ المسترد.

### 11.2 الاشتراكات
| الخطة | الميزات | النموذج المحاسبي |
|---|---|---|
| Free | منتجات محدودة، عمولة أعلى | بدون فاتورة |
| Basic | منتجات أكثر، محاسبة أساسية | شهري/سنوي |
| Professional | محاسبة كاملة، تقارير، مستخدمون متعددون | شهري/سنوي |
| Enterprise | API، تكامل، مدير حساب | عقد سنوي |

الاشتراك السنوي يُعالج كإيراد مؤجل ويُعترف به شهرياً (مبدأ الاستحقاق).

### 11.3 وضع التحصيل اليدوي (أسواق بلا بوابات دفع)

حين يتم الدفع بين المشتري والمورد خارج المنصة (نقداً أو حوالة)، تتغيّر **دورة النقدية** لا المحاسبة:

**دفتر المورد:**
| # | الحدث | مدين | دائن |
|---|---|---|---|
| 1 | إصدار الفاتورة | 1210 العملاء | 4100 المبيعات + 2210 الضريبة |
| 2 | التحصيل المباشر نقداً | 1110 النقدية | 1210 العملاء |
| 3 | استحقاق العمولة | 5150 عمولة المنصة | 2110 مستحق للمنصة |
| 4 | سداد العمولة للمنصة | 2110 مستحق للمنصة | 1110 النقدية |

**دفتر المنصة:**
| # | الحدث | مدين | دائن |
|---|---|---|---|
| 1 | استحقاق العمولة | 1210 ذمم الموردين | 4100 إيراد العمولات |
| 2 | تحصيل العمولة | 1110/1120 النقدية أو البنك | 1210 ذمم الموردين |

> **الفارق الوحيد:** أموال الصفقة لا تمرّ بالمنصة إطلاقاً — تحصّل عمولتها فقط. حسابا الضمان (2120) ورصيد البوابة (1130) يبقيان بلا حركة، والمحفظة (1140) معطّلة.

**ما يلزم إضافته في هذا الوضع:**
- تقرير **"العمولات المستحقة بأعمارها"** لمتابعة تحصيل المنصة من كل مستورد.
- **فاتورة عمولة دورية** (أسبوعية/شهرية) مجمّعة بدل الخصم لكل صفقة.
- **تعليق آلي** لحساب المستورد عند تجاوز سقف دين أو مدة تأخر محددة.
- **تأكيد الصفقة من الطرفين** داخل المنصة — هو الذي يُنشئ استحقاق العمولة، لأن المنصة لا ترى تدفق النقد.

> ⚠️ **المخاطرة الحقيقية في هذا الوضع:** إتمام الصفقة خارج المنصة دون تسجيلها (Disintermediation). التخفيف: ربط العمولة بخدمات لا يحصل عليها المستورد إلا بالتسجيل (الظهور في الدليل، استقبال طلبات عروض الأسعار، المحاسبة، التقييمات)، واعتماد نموذج **اشتراك شهري** بدل العمولة كخيار أساسي في هذا السوق.

## 13. معايير القبول للوحدة المحاسبية

1. ✅ كل قيد متوازن — اختبار آلي يرفض أي قيد غير متوازن.
2. ✅ لا يمكن تعديل أو حذف قيد مرحّل بأي مسار في النظام.
3. ✅ ميزان المراجعة يساوي صفراً في كل مستأجر وكل فترة.
4. ✅ الأصول = الالتزامات + حقوق الملكية في كل لحظة.
5. ✅ رصيد محفظة المورد في دفتره = مستحقاته في دفتر المنصة (تطابق تام).
6. ✅ تعذّر الترحيل في فترة مقفلة.
7. ✅ إعادة تنفيذ نفس الحدث لا تنتج قيداً مكرراً (Idempotency).
8. ✅ تتبّع أي رقم في القوائم المالية وصولاً إلى المستند المصدر بثلاث نقرات.
9. ✅ تغطية اختبارات ≥ 80% لهذه الوحدة.
10. ✅ اعتماد محاسب قانوني لعيّنة من 50 قيداً تغطي كل الأحداث.
